# 로드맵

Stage Planner를 "공연 준비 + 공연 당일 운영" 도구로 넓히는 계획입니다.
기능 명세는 [SPEC.md](SPEC.md), 화면 규칙은 [design.md](design.md)를 보세요.

단계마다 브랜치를 만들어 작업하고, 끝나면 보고하고 멈춥니다.

---

## 끝난 일

### 레포 정리 (완료)

- 대용량 생성물(`stage-planner.html`, `logo_b64.txt`)과 빌드 스크립트(`gen.py`),
  개인 PC 경로가 든 설정 파일을 추적에서 제거
- `.gitignore`, `LICENSE`(Apache-2.0), `NOTICE`, `README`, `CONTRIBUTING` 추가
- 로고를 `assets/brand/`에 정리(세로형 600px, 심볼 128px, 심볼색 #0F2742 확인)

### 기반 전환 (완료)

- 순수 HTML·Canvas 한 파일 → Vite + TypeScript(프레임워크 없음), 테스트는 vitest
- 미터 월드 좌표, 단일 축척(무대 비율 왜곡 제거)
- 회전은 `rot` 하나만 두고 w/d를 맞바꾸지 않음. 회전 사각형 기준 히트테스트
- Pointer Events로 마우스·터치·펜 통합, 두 손가락 이동·핀치 줌
- devicePixelRatio 반영, 명령 단위 되돌리기/다시 실행, IndexedDB 자동 저장
- JSON `version: 1` + 불러오기 검증 + 옛 형식 변환

## 0단계 — 설계 문서 (이번 단계)

- `docs/SPEC.md`: 기능, 데이터 스키마, 화면 목록, 실시간 메시지 형식, 권한,
  보안 위협과 대책, 한계, 열린 질문
- `docs/ROADMAP.md`(이 문서), `docs/design.md`
- 코드는 쓰지 않습니다.

## 1단계 — 모노레포와 공용 스키마

- `packages/app`(프런트), `packages/server`(호스트 서버), `packages/shared`(스키마·계산·메시지 타입)
  로 나눕니다. 지금 `src/`는 `packages/app/src`로 옮기고, 모델·계산은 `shared`로 뺍니다.
- 공용 데이터 스키마(v2)와 검증기를 `shared`에 만듭니다.
- **v1 → v2 변환**을 테스트와 함께 만듭니다(SPEC 5.1).
- Preact + @preact/signals를 넣고 화면 틀을 잡습니다. 캔버스는 지금처럼 직접 그립니다.
- 기존 기능과 테스트가 그대로 통과해야 합니다.

## 2단계 — 무대 설계

- 다각형 무대와 원호, 템플릿 7종(사각 / 앞이 둥근 / 돌출 / 원형 / 중앙 / L자 / 날개)
- 꼭짓점 편집, 높이 구역과 무대 밖 구역, 객석 방향
- 장비 SVG 라이브러리 15종(`assets/equipment/`)과 규격 목록
- 크기·회전 손잡이, 숫자 입력, 스냅
- 무대 밖 배치(FOH, 객석 스택)
- PNG 내보내기와 PDF(**브라우저 인쇄 + print CSS**, 라이브러리 없음). 하단에 새결 로고
- Pretendard 서브셋 글꼴 포함
- **UI에서 이모지를 걷어냅니다.** 지금 버튼과 장비 라벨에 이모지가 쓰여 있는데,
  디자인 규칙과 어긋나므로 아이콘이나 글자로 바꿉니다.

## 3단계 — PA 조언

- `packages/shared/src/audio`에 순수 함수로 계산을 만들고 vitest로 알려진 값과 대조
  (거리 감쇠, SPL 추정, 음원 합산, 지연 시간(온도 보정), dBu/dBV, 임피던스,
  케이블 손실, 전원 용량, 채널 수 점검)
- 공연장 정보 입력 폼, 결과 화면(근거 공식과 가정을 함께 표시)
- 스피커 지향각·커버리지 표시(직접음만 계산하는 추정임을 화면에 명시)
- 결과를 도면에 배치 초안으로 넣기

## 4단계 — 타임테이블

- 항목 편집(리허설, 사운드체크, 공연, 전환, 휴식, 기타)
- 담당·메모·무대 도면 연결
- 시작·종료 기록, 지연 시 뒤 순서 예상 시각 자동 재계산
- 가로 타임라인 보기와 목록 보기

## 5단계 — 로컬 서버와 실시간 동기화

- `npm run host`로 호스트 서버 시작, 접속 주소와 QR 코드 표시, IP 선택
- WebSocket 프로토콜(SPEC 9장), 역할별 접속 코드, 권한 검사
- 재접속 시 전체 상태 다시 받기, 항목 단위 `rev` 충돌 처리
- 사설 IP 대역 제한, 메시지 검증·크기 제한·속도 제한
- **브라우저 창 여러 개로 동시 접속 테스트**를 만들어 확인합니다.

## 6단계 — 대시보드와 공지 화면

- 운영자 대시보드(현재·다음 순서, 남은 시간, 지연, 공지, 접속 기기)
- 대기실·스태프·무대 뒤 큐 화면(읽기 전용 전체 화면, 큰 글씨)
- 긴급 공지 전체 화면 덮기와 확인
- 화면 꺼짐 방지, 연결 끊김 표시와 자동 재접속

## 7단계 — 공개 준비

- 사용자 문서, 스크린샷, 설치·실행 안내
- 기여 가이드 보완, 이슈 템플릿
- 실기기 점검표(iPad Safari, 안드로이드 Chrome, 윈도우 터치)
- 의존성 라이선스 정리와 NOTICE 반영
