# Stage Planner 기능 명세

이 문서는 Stage Planner가 무엇을 하는 도구인지, 데이터를 어떻게 담는지,
기기끼리 어떻게 주고받는지를 적습니다. 구현 순서는 [ROADMAP.md](ROADMAP.md),
화면 규칙은 [design.md](design.md)를 보세요.

문서 상태: 0단계(설계) 산출물입니다. 아직 구현되지 않은 내용이 대부분이며,
구현하면서 달라진 부분은 이 문서를 먼저 고칩니다.

---

## 1. 개요와 범위

Stage Planner는 공연 하나를 **준비**하고 **당일 운영**하는 도구입니다.

하는 일

- 무대 배치도를 만듭니다. 무대 형태를 정하고 장비를 실제 크기로 놓습니다.
- 공연장 조건을 넣으면 PA 기본 세팅 초안을 계산해 줍니다.
- 하루 순서(타임테이블)를 만들고, 공연 중에 실제 시각을 기록합니다.
- 같은 와이파이에 있는 기기들이 호스트에 접속해 같은 내용을 실시간으로 봅니다.
- 대기실 TV나 스태프 태블릿에 현재 순서와 공지를 띄웁니다.

하지 않는 일 (비범위)

- **전문 음향 시뮬레이터를 대신하지 않습니다.** 반사, 간섭, 실내 음향을 계산하지
  않습니다. 직접음 기준의 거친 추정만 제공합니다.
- 제조사 스피커 데이터를 내장하지 않습니다. 제원은 사용자가 넣습니다.
- 인터넷 서비스가 아닙니다. 계정, 클라우드 저장, 외부 공유 기능이 없습니다.
- 티켓, 정산, 출연료 같은 공연 사무 기능은 다루지 않습니다.

## 2. 용어

| 용어 | 뜻 |
|---|---|
| Event | 공연 하루 전체. 저장·불러오기의 단위입니다. |
| Venue | 공연장 정보(크기, 천장, 수용 인원, 전원 사정). |
| StagePlan | 무대 배치도 한 장. 한 Event에 여러 장을 둘 수 있습니다(팀별 세팅). |
| Zone | 무대 위 높이가 다른 구역이나 무대 밖 구역(객석, FOH, 출입구). |
| Timetable | 하루 순서 목록. |
| Notice | 공지. 일반과 긴급이 있습니다. |
| Device | 호스트에 접속한 기기 하나. |
| 호스트 | 로컬 서버를 띄운 기기(보통 운영자 노트북). 데이터의 단일 원본입니다. |

## 3. 역할과 권한

접속할 때 역할별 6자리 접속 코드를 넣습니다. 역할은 접속 코드로 정해집니다.

화면에서는 공연장에서 쓰는 말로 부릅니다. 저장 파일과 접속 코드가 흔들리지 않도록
**프로토콜의 이름(operator/staff/display)은 그대로 둡니다.**

| 화면에서 부르는 이름 | 프로토콜 이름 |
|---|---|
| FOH | `operator` |
| 운영팀 | `staff` |
| 대기실 | `display` |

| 역할 | 할 수 있는 일 |
|---|---|
| FOH (operator) | 모든 편집. 공지·지시 보내기, 순서 시작·종료, 접속 기기 끊기. |
| 운영팀 (staff) | 받은 지시 처리 표시, 자기가 담당인 순서의 상태 변경. 그 외는 읽기만. |
| 대기실 (display) | 읽기 전용. 편집 요청을 보내면 서버가 거부합니다. 공지 확인(읽음 표시)만 예외입니다 — 대기실 화면이 공지를 직접 닫아야 하기 때문입니다. |

권한은 **서버에서** 확인합니다. 화면에서 버튼을 숨기는 것은 편의일 뿐이고,
서버가 역할을 보고 모든 편집 요청을 검사합니다.

## 4. 화면 목록

앱을 열면 **시작하기 화면**에서 자리를 먼저 고릅니다. 고른 자리는 그 기기에
기억해 두고, 자리에 따라 보이는 화면이 달라집니다.

| 자리 | 첫 화면 | 보이는 화면 |
|---|---|---|
| FOH | 대시보드 | 대시보드 · 타임테이블 · 무대 설계 · PA 조언 · 호스트 |
| 운영팀 | 대시보드 | 대시보드 · 타임테이블 · 무대 설계 · 호스트 |
| 대기실 | 공지 | 공지 · 타임테이블 · 무대 설계 · 호스트 |

| # | 화면 | 기본 테마 | 쓰는 사람 |
|---|---|---|---|
| 1 | 시작하기(자리 고르기·접속) | 라이트 | 모두 |
| 2 | 무대 설계 | 라이트 | FOH, 운영팀(읽기) |
| 3 | 공연장 정보 + PA 조언 | 라이트 | FOH |
| 4 | 타임테이블 편집 | 라이트 | FOH |
| 5 | 대시보드 | 다크 | FOH, 운영팀 |
| 6 | 대기실 공지 화면 | 다크 | 출연자 |
| 7 | 호스트·연결 화면 | 라이트 | 모두 |

- **PA 조언은 FOH에만** 보입니다. 다른 자리에서는 탭 자체가 없습니다.
- **호스트 화면은 모든 자리에** 있습니다. 접속 상태를 늘 확인할 수 있어야 하기
  때문입니다.
- 운영팀 대시보드는 FOH와 **같은 모양**이고, 보내기 칸만 빠집니다.

- **1~3은 호스트 없이 혼자서도 완전히 동작합니다**(로컬 저장만 사용).
  무대 설계뿐 아니라 타임테이블 편집과 진행 기록까지 포함합니다.
  호스트는 "이미 만든 것을 다른 기기와 실시간으로 나누는" 선택 기능입니다.
- 4~7은 호스트 접속이 필요합니다.
- 5~7은 읽기 전용 전체 화면입니다. 멀리서 읽히는 큰 글씨를 씁니다.

### 4.1 대시보드 (5)

왼쪽에 지금 순서·남은 시간·다음 순서·누적 지연과 타임테이블 요약을 둡니다.
오른쪽에 **지금 떠 있는 글**(대기실 공지와 운영팀 지시)을 둡니다. FOH에는 그
아래에 보내기 칸과 접속 기기 목록이 더 붙습니다.

타임테이블 요약의 도면 단추를 누르면 그 순서의 배치도로 바로 갑니다.
태블릿 가로 화면과 노트북 화면에 맞춥니다.

### 4.2 대기실 공지 화면 (6)

띄워 둔 공지가 있으면 **단색 배경에 중앙 정렬 큰 글씨**로 그것만 보여 줍니다.
아래에 지금·다음 순서와 콜 타임을 한 줄로 둡니다. 공지가 없으면 지금 순서,
남은 시간, 다음 순서, 콜 타임을 큰 글씨로 보여 줍니다.

확인 단추를 누르면 그 기기에서만 공지가 사라지고, FOH 화면에는 몇 대가
확인했는지 보입니다. 공지를 모두에게서 내리는 것은 FOH의 "내리기"입니다.

공통 동작

- 긴급 공지가 오면 화면 전체를 덮습니다. 확인 버튼이나 운영자 해제로 닫힙니다.
- 화면 꺼짐 방지(Wake Lock API를 지원하는 브라우저에서만).
- 연결이 끊기면 마지막 내용을 그대로 두고 "연결 끊김"을 표시한 뒤 자동으로 다시 붙습니다.

## 5. 데이터 스키마

모든 좌표와 크기는 **미터**입니다. 각도는 도(°)이고 시계 방향입니다.
저장 파일 최상위에 `version`을 둡니다. 현재 버전은 **2**입니다.

**Event 하나는 하루입니다.** 여러 날짜가 필요해지면 그때 상위 개념(Festival 등)을
얹습니다. 지금 스키마를 넓히지 않습니다.

실시간으로 함께 고치는 단위(StagePlan, TimetableItem, Notice)에는 `rev`(정수)를 둡니다.
고칠 때마다 서버가 1씩 올립니다. 충돌 처리에 씁니다(9.4).

```ts
interface Event {
  version: 2;
  id: string;
  name: string;          // "2026 봄 정기공연"
  date: string;          // YYYY-MM-DD
  venue: Venue;
  pa: PaSetup;           // PA 조언 입력(편성, 장르, 스피커 제원)
  stagePlans: StagePlan[];
  timetable: Timetable;
  notices: Notice[];
  devices: Device[];     // 런타임 정보. 파일로 저장할 때는 비웁니다.
  accessCodes: AccessCodes; // 역할별 접속 코드. 공연마다 하나씩 유지합니다
}

// 호스트를 껐다 켜도 같은 코드를 씁니다. 재발급은 화면의 버튼으로만 합니다.
// 코드는 JSON 내보내기에서 기본으로 빠집니다(10장).
interface AccessCodes {
  operator: string;      // 6자리
  staff: string;
  display: string;
  rotatedAt: string;     // 마지막 재발급 시각(ISO)
}

interface Venue {
  name: string;
  widthM: number;        // 공연장 가로
  depthM: number;        // 공연장 깊이
  ceilingM: number;      // 천장 높이
  indoor: boolean;       // 실내/야외
  capacity: number;      // 수용 인원
  stageToBackM: number;  // 무대 앞에서 객석 맨 뒤까지
  tempC: number;         // 음속 보정용 기온. 기본 20
  power: {
    circuits: number;       // 쓸 수 있는 회로 수
    ampsPerCircuit: number; // 회로당 암페어. 기본 16
    voltage: number;        // 기본 220
  };
}

interface StagePlan {
  id: string;
  name: string;          // "1팀 세팅"
  stage: StageShape;
  zones: Zone[];
  objects: StageObject[];
  notes: Note[];
  audienceDir: "front" | "all" | number; // "all"은 중앙 무대, 숫자는 각도
  rev: number;
}

interface StageShape {
  points: Vec2[];        // 다각형 꼭짓점. 시계 방향
  arcs?: ArcSegment[];   // 일부 변을 원호로
}

interface ArcSegment {
  fromIdx: number;       // points의 인덱스
  toIdx: number;
  bulgeM: number;        // 현 중앙에서 호까지의 거리. 양수면 바깥쪽
}

interface Zone {
  id: string;
  kind: "riser" | "level" | "audience" | "foh" | "exit" | "backstage";
  name: string;
  polygon: Vec2[];
  heightM?: number;      // riser, level일 때 무대 바닥 기준 높이
}

interface StageObject {
  id: string;
  type: string;          // 장비 종류 키 (6장)
  variantId?: string;    // 규격 선택 (6장)
  x: number; y: number;  // 회전하지 않은 사각형의 왼쪽 위 모서리
  w: number; d: number;  // 가로, 깊이
  h: number;             // 높이. 평면도에는 그리지 않습니다
  z: number;             // 바닥에서 띄운 높이 (라이저 위 등)
  rot: number;           // 중심 기준 회전각
  label: string;
  color?: string;        // 없으면 장비 기본색
  onStage: boolean;      // false면 무대 밖(FOH, 객석 스택)
  locked?: boolean;
}

interface Note {         // 기존 포스트잇
  id: string;
  x: number; y: number;  // 중심
  text: string;
  role: string;
  color: string;
  linkedObjectId: string | null;
}

interface Timetable {
  dayStart: string;      // HH:MM. 첫 항목의 기본 시작
  items: TimetableItem[];
}

interface TimetableItem {
  id: string;
  kind: "rehearsal" | "soundcheck" | "show" | "changeover" | "break" | "other";
  title: string;
  plannedStart: string;       // HH:MM
  durationMin: number;
  owner: string;              // 담당
  memo: string;
  stagePlanId: string | null; // 이 순서의 세팅 도면
  actualStart: string | null; // ISO 시각. 서버 시계
  actualEnd: string | null;
  status: "pending" | "running" | "done";
  rev: number;
}

// 보내는 글은 두 종류입니다. 받는 사람도 생김새도 다릅니다.
//  - announce: 대기실 공지. 단색 배경에 큰 글씨로 띄웁니다.
//  - cue: 운영팀 지시. 무엇을 할지 적고 처리 여부를 표시합니다.
interface Notice {
  id: string;
  kind: "announce" | "cue";
  level: "normal" | "urgent";
  text: string;
  targets: ("operator" | "staff" | "display")[];
  createdAt: string;     // ISO. 서버 시계
  ackBy: string[];       // 확인(또는 처리)한 deviceId
  cueKind?: "mic" | "stage" | "instrument" | "move" | "other"; // kind가 cue일 때
  itemId?: string | null; // 어느 순서에 대한 지시인지
  closedAt?: string | null; // 내린 시각. 값이 있으면 화면에서 사라집니다
  rev: number;
}

interface Device {
  id: string;
  role: "operator" | "staff" | "display";
  name: string;          // "대기실 TV"
  connectedAt: string;
  lastSeen: string;
  status: "online" | "stale" | "offline";
}

// PA 조언의 입력. 공연마다 다르므로 Event에 함께 저장합니다. 스피커 제원은
// 프리셋에서 고른 값을 복사해 둡니다. 복사하지 않으면 프리셋이 없는 다른 기기에서
// 같은 파일을 열었을 때 조언이 달라집니다.
interface PaSetup {
  genre: "acoustic" | "band" | "rock" | "electronic";
  lineup: {
    vocals: number;                 // 보컬 마이크 수
    entries: { instrumentId: string; count: number }[];
  };
  speakerName: string;              // 프리셋 이름(표시용)
  speaker: SpeakerSpec;             // 프리셋에서 복사한 제원
  mixerChannels: number;            // 쓸 수 있는 믹서 입력 채널 수
}

// 스피커 제원 프리셋. Event에 넣지 않고 기기에 로컬로 저장해 여러 공연에서 씁니다.
interface SpeakerPreset {
  id: string;
  name: string;          // "메인 15인치"
  sensitivityDb: number; // dB @1W/1m
  maxSplDb: number;
  dispersionH: number;   // 수평 지향각(도)
  dispersionV: number;
  powerW: number;
}
```

### 5.1 버전 1 → 2 변환

현재 v1 파일은 `{ version: 1, stage: {w,d,h}, objects[], postits[], customTypes }`
구조입니다(`src/model/types.ts`). 변환 규칙:

| v1 | v2 |
|---|---|
| 파일 전체 | `Event` 하나 + `StagePlan` 하나 |
| `stage.w`, `stage.d` | `StageShape.points` 네 점 (0,0) (w,0) (w,d) (0,d) |
| `stage.h` | 쓰지 않습니다. 무대 높이는 `Zone.heightM`으로 옮겨 갑니다 |
| `objects[]` | `StageObject[]`. `emoji`는 버리고 `type`으로 그림을 찾습니다. id는 문자열로 |
| `postits[]` | `Note[]`. `nm` → `text`, `con` → `linkedObjectId` |
| `customTypes` | 사용자 추가 장비로 유지. 그림은 기본 사각형 |
| 없음 | `Venue`, `Timetable`, `Notice`는 빈 기본값 |

변환은 **되돌릴 수 없습니다**. v2를 v1로 저장하지 않습니다. 불러올 때 한 번
변환하고, 사용자에게 "옛 형식을 새 형식으로 바꿔 열었습니다"라고 알립니다.
변환 함수는 테스트와 함께 1단계에서 만듭니다.

## 6. 장비 라이브러리

### 6.1 그림 규칙

장비는 **파라메트릭 그리기 코드**로 그립니다(`packages/shared/src/draw/shapes.ts`).
정적 SVG 파일을 쓰지 않습니다. 규격에 따라 모양이 실제로 달라져야 하기 때문입니다.

- 드럼킷은 `variantId`가 투베이스면 킥 드럼을 둘 그립니다.
- 키보드는 깊이가 0.6m 이상이면 2단, 가로 1.2m 이상이면 건반을 52개로 그립니다.
- 스피커는 가로세로비가 1.6 이상이면 라인 어레이 리깅 프레임을 더 그립니다.
- 서브우퍼는 가로에 따라 드라이버 수가 1~4개로 바뀝니다.

정적 SVG로는 이 변화를 담을 수 없어 코드로 둡니다. 출발점은
`docs/reference/blocks.patch`의 `SHAPES`입니다.

규칙

- 함수마다 장비 중심이 원점, 단위는 px, **앞쪽이 +y**입니다. `s`는 1m당 px입니다.
- 그림 키(`draw`)로 함수를 고릅니다. 기타 앰프와 베이스 앰프처럼 같은 그림을
  쓰는 장비가 있습니다(6.2).
- 선 굵기와 색은 함수 안에서 통일해 씁니다. 색은 분류색 하나를 받아
  투명도만 달리합니다(`hexA`).
- **제조사 로고, 제품 사진, 제조사 도면을 베끼지 않습니다.** 누가 봐도 그 장비인
  일반적인 형태만 그립니다.
- 사용자가 추가한 장비는 `custom`(기본 사각형)을 씁니다.

장비 색은 종류마다 다르게 두지 않고 **분류 셋**으로만 구분합니다.
무지개 색으로 장비를 구분하지 않는다는 디자인 규칙을 따릅니다.

## 7. 무대 형태

### 7.1 다각형과 원호

무대는 사각형 하나가 아니라 **다각형**(`StageShape.points`)입니다. 일부 변은
원호(`StageShape.arcs`)로 둘 수 있습니다.

```ts
interface ArcSegment { fromIdx: number; toIdx: number; bulgeM: number }
```

변 `i`는 꼭짓점 `i`에서 `i+1`로 가고, 그 변의 원호는 `fromIdx === i`인 항목
하나뿐입니다. `toIdx`는 늘 `(fromIdx + 1) % n`입니다. 불러올 때 이 규칙을
어기는 항목은 버립니다(5장).

**부푼 거리(`bulgeM`)의 부호** — 변 `a→b`의 단위 법선을
`n = ((b.y − a.y), −(b.x − a.x)) / |b − a|`로 둡니다. 양수는 호의 중점을 현의
중점에서 `n` 방향으로 `bulgeM`만큼 밀어냅니다. 템플릿은 화면 좌표(y가 아래쪽)에서
시계 방향으로 감겨 있어 **양수가 무대 바깥쪽(볼록), 음수가 안쪽(오목)** 입니다.
0은 직선이며 `ArcSegment`를 두지 않습니다.

현의 절반을 `h`, 부푼 거리를 `s`라 하면 반지름은 `R = (h² + s²) / 2|s|` 이고,
중심은 현의 중점에서 법선 반대쪽으로 `R − |s|`만큼 간 곳입니다. `|s| = h`이면
반원입니다.

**선분으로 펴기** — `tessellate(shape, toleranceM)` 하나가 무대 모양의 단일
진실입니다. 그리기, 히트테스트, 경계 제한, 내보내기가 모두 이 함수를 거치고,
따로 계산하는 코드는 두지 않습니다. 선분이 호에서 벗어나는 최대 거리는
`R(1 − cos(θ/2))`이므로, 허용오차 `t`를 지키는 분할 각도는
`θ = 2·acos(1 − t/R)` 입니다.

허용오차는 쓰임에 따라 다릅니다.

| 쓰임 | 허용오차 |
|---|---|
| 기본(경계상자, 히트테스트, 경계 제한) | 5mm |
| 화면·내보내기 그리기 | 화면 0.35px를 월드로 환산 |

기본값을 5mm로 좁힌 이유는 정확도 때문만이 아닙니다. 느슨하면 곡선의 끝이 덜
잡혀 무대 가로·세로가 실제보다 작게 측정되고, 그 값으로 템플릿을 다시 만들면
무대가 조금씩 줄어듭니다.

### 7.2 템플릿

| 템플릿 | 꼭짓점 | 원호 | 설명 |
|---|---|---|---|
| 사각형 | 4 | — | 기본. 가로 × 깊이 |
| 앞이 둥근 무대 | 4 | 1 | 뒤와 옆은 직선, 앞 변만 바깥으로 부푼 호 |
| 돌출 무대 (thrust) | 8 | — | 사각형 앞에 돌출부가 붙은 형태 |
| 원형 | 4 | 4 | 축 끝점 네 개와 사분원 네 개 |
| 중앙 무대 | 4 | — | 사방이 객석. `audienceDir`가 `all` |
| L자 | 6 | — | 꺾인 무대 |
| 날개 있는 무대 | 12 | — | 좌우에 날개가 붙은 형태 |

템플릿은 가로·깊이를 받아 `points`와 `arcs`를 만들어 주는 함수일 뿐입니다.
만든 뒤에는 모두 똑같이 꼭짓점과 변을 편집할 수 있습니다.

원형 템플릿은 가로 = 세로이면 **정확한 원**이고(사분원의 부푼 거리가
`r(1 − cos45°) ≈ 0.2929r`), 가로 ≠ 세로이면 타원을 원호 넷으로 **근사**합니다.
근사는 짧은 축 쪽으로 최대 5%쯤 넘치므로, 부푼 거리를 한 배율로 줄여 요청한
가로 × 세로 안에 들어오게 맞춥니다. 그렇게 하지 않으면 템플릿을 다시 적용할
때마다 무대가 자랍니다.

### 7.3 편집

**꼭짓점** — 무대 모양 모드에서 꼭짓점 손잡이(채운 원)를 끌어 옮깁니다. 탭하면
속성 바에 번호와 X·Y가 나오고 거기서 지웁니다(Delete 키도 같습니다). 꼭짓점은
세 개 아래로 줄이지 않습니다.

**변** — 변 중점 손잡이(작은 빈 원)를 끌면 그 변이 호가 됩니다. 포인터를 변의
법선에 투영해 부푼 거리를 구하므로 변을 따라 흐르는 움직임은 무시됩니다. 끄는
동안 부푼 거리를 숫자로 보여 주고, 스냅이 켜져 있으면 격자 단위로 맞춥니다.
안쪽으로 끌면 오목해지고, 더블탭하거나 원래 선 위로 되돌리면 직선이 됩니다.
손잡이는 호가 있으면 호의 중점에 놓여 곡선을 따라갑니다.

**번호 보정** — 꼭짓점을 지우거나 더하면 원호의 `fromIdx`/`toIdx`가 어긋납니다.
보정 규칙은 `shapeEdit.ts`에 순수 함수로 모아 두고 테스트로 덮습니다.

- 지운 꼭짓점에 닿던 호(그 꼭짓점에서 나가는 변과 들어오는 변)는 **버립니다**.
  두 변이 하나로 합쳐지므로 어느 쪽 부푼 거리를 물려받을 근거가 없습니다.
- 남은 호의 번호는 한 칸 내리고, `toIdx`는 새 길이로 다시 모듈로를 취합니다.
- 꼭짓점을 끼우면 쪼개진 변의 호는 버리고 뒤쪽 번호는 한 칸 올립니다.

### 7.4 구역

구역(`Zone`)은 다각형이며 종류가 여섯입니다.

| 종류 | 자리 | 높이 입력 | 테두리 |
|---|---|---|---|
| 라이저 `riser` | 무대 위 | 받음 | 실선 |
| 단차 `level` | 무대 위 | 받음 | 실선 |
| 객석 `audience` | 무대 밖 | 안 받음 | 점선 |
| FOH `foh` | 무대 밖 | 안 받음 | 점선 |
| 출입구 `exit` | 무대 밖 | 안 받음 | 점선 |
| 대기실 동선 `backstage` | 무대 밖 | 안 받음 | 점선 |

- **만들기**: 구역 모드에서 종류를 고르고 무대 위나 밖을 끌면 사각형 구역이
  생깁니다. 터치에서 점을 하나씩 찍게 하지 않습니다. 가로·세로가 0.3m 미만이면
  손이 떨린 것으로 보고 버립니다.
- **고치기**: 선택하면 꼭짓점 손잡이가 나옵니다. 끌어 옮기고, 변 중점을 탭해
  꼭짓점을 더합니다. 속성 바에서 이름·종류·높이를 바꿉니다. 종류를 무대 밖
  종류로 바꾸면 높이가 사라지고, 라이저·단차로 되돌리면 기본값 0.4m가 붙습니다.
- **보이기**: 무대 바닥보다 위, 장비보다 아래에 그립니다. 장비를 가리지 않도록
  채움은 옅게(알파 0.14) 하고 테두리로 구분합니다. **색만으로 구분하지 않고
  이름을 늘 함께 적습니다.** 라이저·단차는 이름 옆에 높이를 적습니다
  ("드럼 라이저 0.4m"). 도구 모음의 체크박스로 구역 표시를 끄고 켭니다.
- **겹침**: 막지 않습니다. 겹친 자리를 탭하면 나중에 만든 것을 고릅니다.
- 모든 편집은 되돌리기/다시 실행에 들어갑니다.

**라이저와 장비** — 장비 중심이 `riser`/`level` 구역 안에 들어가면 속성 바에
"드럼 라이저 0.4m 위"처럼 **표시만** 합니다. `StageObject.z`를 자동으로 바꾸지는
않습니다.

### 7.5 객석 방향과 무대 밖 배치

- 장비는 무대 밖에도 놓을 수 있습니다(`StageObject.onStage`가 false).
  FOH 믹서나 객석 쪽 스피커 스택이 여기에 해당합니다.
- 객석 방향은 배치도마다 정합니다. 중앙 무대와 원형 무대는 사방이 객석입니다.
  이 값은 화면의 정면 표시와 PA 조언의 기준 방향에 쓰입니다.

## 8. PA 기본 세팅 조언

### 8.1 입력

공연장 가로·깊이·천장 높이, 실내/야외, 수용 인원, 장르(어쿠스틱 / 밴드 / 록 /
전자음악), 편성(악기 종류와 수, 보컬 수), 무대에서 객석 맨 뒤까지 거리, 기온,
전원 사정(회로 수, 회로당 암페어). 스피커 제원(감도 dB@1W/1m, 최대 음압, 지향각,
정격 출력)은 **사용자가 넣습니다.**

자주 쓰는 스피커 제원은 **프리셋으로 기기에 저장**해 두고 다음 공연에서는 고르기만
하면 됩니다(`SpeakerPreset`, 5장). 프리셋은 Event 파일이 아니라 기기에 남습니다.

### 8.1.1 조언 규칙

조언은 아래 규칙으로만 만듭니다. 규칙과 기준값은 모두 화면에 근거로 적습니다.

| 항목 | 규칙 |
|---|---|
| 메인 형식 | 수용 300명 이상이거나 맨 뒤 25m 이상이면 라인 어레이, 아니면 포인트 소스 |
| 메인 대수 | 한 대가 맨 뒤에서 내는 음압과 장르 목표 음압의 차이를 메우는 대수. 한쪽 4대까지 |
| 목표 음압 | 어쿠스틱 95 / 밴드 100 / 록 103 / 전자음악 103 dB |
| 서브우퍼 | 장르별로 한쪽 0·1·1·2대씩 좌우 |
| 딜레이 스피커 | 맨 뒤 25m 이상이거나 목표 음압에 못 미치면. 자리는 맨 뒤의 절반 거리 |
| 딜레이 시간 | 그 거리를 소리가 지나는 시간 + 하스 여유 10ms |
| 모니터 믹스 | 보컬 수 + 모니터가 필요한 악기 자리 수. 최대 8개 |
| 전원 | 백라인 대표값 + PA(메인은 정격의 35%, 서브 400W, 모니터 150W, 믹서 150W) |
| 회로 | 회로 하나에 정격의 80%까지만 겁니다 |

악기별 입력 채널·마이크·스탠드와 대표 소비 전력은
`packages/shared/src/audio/lineup.ts`에 표로 두고 테스트로 고정합니다.

### 8.2 출력

- 메인 스피커 구성(포인트 소스 / 라인 어레이, 대수)과 서브우퍼 수
- 딜레이 스피커 필요 여부와 지연 시간
- 객석 맨 앞·맨 뒤 예상 음압(직접음 기준)
- 모니터 믹스 수
- 입력 채널 리스트 초안(채널 번호, 소스, 마이크 종류, 스탠드 종류)
- 믹서 채널 수가 모자라지 않는지 점검
- 전원 합계 전류와 회로별 배분 점검

### 8.3 공식

계산은 `packages/shared/src/audio`에 **순수 함수**로 두고 vitest로 알려진 값과
대조합니다. 화면에는 근거 공식과 가정을 같이 보여 줍니다.

| 항목 | 공식 |
|---|---|
| 음속 | c = 331.3 + 0.606 × T(°C) (m/s) |
| 지연 시간 | t = d / c (초). 딜레이 스피커 정렬에 씁니다 |
| 거리 감쇠 | ΔSPL = 20 × log10(d2 / d1) (dB) |
| 스피커 도달 음압 | SPL = 감도 + 10 × log10(W) − 20 × log10(d) |
| 음원 합산(비간섭) | L = 10 × log10(Σ 10^(Li/10)) |
| dBu ↔ dBV | dBV = dBu + 20 × log10(0.7746), 약 dBu − 2.21 |
| 전원 전류 | I = ΣP / V (V는 기본 220) |

### 8.4 가정과 한계 (화면에 같이 표시)

- **직접음만 계산합니다.** 반사, 간섭, 잔향, 실내 음향을 넣지 않습니다.
- 공기 흡수와 지향각에 따른 감쇠를 단순하게만 다룹니다.
- 제조사 데이터를 내장하지 않습니다. 제원이 틀리면 결과도 틀립니다.
- **전문 음향 시뮬레이터를 대신하지 않습니다.** 현장 확인이 필요합니다.
- 조언은 정해진 규칙과 공식으로만 만듭니다. 추측하지 않습니다.

### 8.5 도면에 반영

조언 결과를 버튼 하나("배치 초안 넣기")로 현재 StagePlan에 넣습니다.
메인 스피커, 서브우퍼, 모니터, FOH 믹서를 계산된 수량과 위치로 놓습니다.
기존 배치를 지우지 않고 **되돌리기 한 단계**로 취소할 수 있게 합니다.

## 8.6 타임테이블 계산

순서는 목록에 적힌 차례대로 이어집니다. 각 순서의 예상 시각은 이렇게 구합니다.

| 상태 | 시작 | 끝 |
|---|---|---|
| 끝남 | 실제 시작 | 실제 종료 |
| 진행 중 | 실제 시작 | 실제 시작 + 예정 길이. 이미 지났으면 지금 시각 |
| 대기 | 앞 순서가 끝난 시각과 계획 시각 중 **늦은 쪽** | 시작 + 예정 길이 |

- 앞 순서가 일찍 끝나도 계획보다 먼저 시작하지 않습니다. 출연자가 와 있지 않기
  때문입니다.
- **누적 지연은 아직 안 끝난 순서 기준**입니다. 이미 끝난 순서의 지연은 되돌릴 수
  없고, 운영자가 알고 싶은 것은 "지금부터 얼마나 밀렸는지"입니다.
- 진행 중인 순서가 예정 길이를 넘기면 끝 시각을 지금 시각까지 늘립니다. 그래야 뒤
  순서가 현실에 맞게 밀립니다.
- 계획 시각이 비어 있으면 앞 순서에 바로 붙입니다.
- 한 번에 하나만 진행 중입니다. 다른 순서를 시작하면 앞선 순서를 자동으로 끝냅니다.
- 자정을 넘기면 분을 1440 위로 이어서 세고, 화면에는 "다음 날"을 붙입니다.
  날짜가 다른 공연은 Event를 나눕니다(5장).

실제 시각은 기기의 현지 시각으로 기록합니다. 호스트에 붙으면 서버 시각을
기준으로 바꿉니다(9장).

## 9. 실시간 연결

### 9.1 구조

호스트 한 대(보통 운영자 노트북)가 Node 서버를 띄웁니다. 같은 와이파이의 다른
기기는 브라우저로 `http://<호스트 IP>:<포트>` 에 접속합니다. 인터넷이 없어도
동작합니다. 실시간 통신은 WebSocket입니다.

**호스트가 단일 원본입니다.** 클라이언트끼리 직접 고치지 않고, 모든 변경은
서버를 거쳐 모두에게 전달됩니다.

호스트를 시작하면 접속 주소와 QR 코드를 화면에 띄웁니다. 호스트 IP는 자동으로
찾되, 네트워크가 여럿이면 목록에서 고르게 합니다.

### 9.2 메시지 봉투

JSON 한 줄, 메시지당 **64KB 상한**입니다.

```ts
{ t: string, seq?: number, payload: object }
```

### 9.3 메시지 목록

클라이언트 → 서버

| t | payload | 설명 |
|---|---|---|
| `hello` | `{ code, role, deviceName }` | 접속. 코드가 틀리면 `error` 후 끊습니다 |
| `patch` | `{ entity, id, rev, changes }` | 항목 수정 |
| `ack` | `{ noticeId }` | 공지 확인 |
| `itemStart` | `{ itemId }` | 순서 시작(실제 시각 기록) |
| `itemEnd` | `{ itemId }` | 순서 종료 |
| `ping` | `{}` | 살아 있음 확인 |

서버 → 클라이언트

| t | payload | 설명 |
|---|---|---|
| `welcome` | `{ deviceId, role, serverTime, snapshot }` | 접속 성공. 전체 상태 |
| `snapshot` | `{ serverTime, snapshot }` | 전체 상태 다시 보내기 |
| `patched` | `{ entity, id, rev, changes, by }` | 다른 기기의 변경 전파 |
| `conflict` | `{ entity, id, serverRev, serverValue }` | 내 수정이 밀렸음 |
| `notice` | `{ notice }` | 공지 도착 |
| `devices` | `{ devices }` | 접속 기기 목록 변경 |
| `kicked` | `{ reason }` | 운영자가 끊음 |
| `error` | `{ code, message }` | 거부 사유 |
| `pong` | `{}` | |

### 9.3.1 추가 메시지

SPEC을 쓸 때 없던 메시지 셋을 구현하면서 더했습니다.

| t | 방향 | payload | 설명 |
|---|---|---|---|
| `notice` | 클→서 | `{ level, text, targets }` | 운영자가 공지를 보냅니다 |
| `publish` | 클→서 | `{ snapshot }` | 운영자가 자기 기기의 작업을 호스트에 올립니다 |
| `kick` | 클→서 | `{ deviceId }` | 운영자가 기기를 끊습니다 |
| `noticeClose` | 클→서 | `{ noticeId }` | 띄워 둔 공지나 처리한 지시를 내립니다 |

**`publish`를 둔 이유** — 호스트는 빈 공연으로 시작하고, 운영자는 이미 자기
기기에서 도면과 순서를 만들어 둔 상태로 붙습니다. 그 작업을 호스트에 올리는
길이 필요합니다. 올린 뒤에는 호스트가 단일 원본이고, 운영자가 고친 것은
0.4초 모아서 다시 `publish`로 올라갑니다. 도면 편집은 한 번에 여러 항목을
건드리고 운영자는 보통 한 명이기 때문입니다. 여럿이 같은 항목을 고치는
경우는 `patch`와 `rev`로 거릅니다.

### 9.4 충돌 처리

항목 단위 `rev`로 처리합니다.

1. 클라이언트가 `patch`에 자기가 아는 `rev`를 같이 보냅니다.
2. 서버의 `rev`와 같으면 적용하고 `rev`를 1 올린 뒤 모두에게 `patched`를 보냅니다.
3. 다르면 **나중에 온 것이 이깁니다.** 적용하되, 밀린 쪽에게 `conflict`를 보내
   "다른 사람이 먼저 고쳤습니다"를 화면에 띄웁니다. 값을 조용히 덮지 않습니다.

### 9.5 재접속

연결이 끊기면 클라이언트가 자동으로 다시 붙고 `hello`를 다시 보냅니다.
서버는 **전체 `snapshot`을 다시 보냅니다.** 부분 복구는 하지 않습니다.
끊겨 있는 동안 표시 화면은 마지막 내용을 그대로 두고 "연결 끊김"을 표시합니다.

### 9.5.1 읽기 전용 화면

운영자가 아닌 역할로 붙으면 **화면에서도 편집을 막습니다.** 서버가 거부하더라도
화면에서 고쳐지는 것처럼 보이면 내 기기의 내용만 조용히 달라지기 때문입니다.
장비 팔레트와 편집 도구를 감추고 "읽기 전용입니다"를 적습니다. 스태프의
순서 시작·종료만 남기고, 그 권한은 서버가 담당자 이름으로 확인합니다.

### 9.6 시계

남은 시간과 지연 계산은 **서버 시각을 기준**으로 합니다. `welcome`에 `serverTime`을
실어 보내 클라이언트가 자기 시계와의 차이를 재어 두고, 표시할 때 보정합니다.
기기 시계가 틀려도 모두 같은 숫자를 봅니다.

호스트 없이 혼자 쓸 때는 기기 시각을 그대로 씁니다. 기준이 하나뿐이라 어긋날 일이 없습니다.

## 10. 보안 위협과 대책

이 도구는 **믿을 수 있는 로컬 네트워크**에서 쓰는 것을 전제로 합니다.
인터넷에 열어 두는 용도가 아닙니다.

| 위협 | 대책 |
|---|---|
| 외부망에 노출됨 | 기본으로 사설 IP 대역(10/8, 172.16/12, 192.168/16, 127/8)에서 오는 연결만 받습니다. 그 외는 거부하고, 해제는 명시적 옵션으로만 합니다 |
| 모르는 사람이 접속 | 역할별 6자리 접속 코드. 호스트를 시작할 때 새로 만들고 호스트 화면에만 보여 줍니다. 운영자가 접속 기기를 끊을 수 있습니다 |
| 코드 무차별 대입 | 접속 실패를 기기·IP 단위로 세어 속도를 제한하고, 일정 횟수를 넘기면 잠시 막습니다 |
| 악성·과대 메시지 | 모든 메시지를 스키마로 검증합니다. 모르는 필드는 버리고, 64KB를 넘으면 끊습니다. 메시지 빈도도 제한합니다 |
| 권한 우회 | 역할 검사는 서버에서 합니다. 화면에서 버튼을 숨기는 것은 편의일 뿐입니다 |
| XSS | 사용자 문자열은 textContent로만 넣습니다. `innerHTML`과 `dangerouslySetInnerHTML`을 쓰지 않습니다 |
| 접속 코드 유출 | 코드를 로그, PNG·PDF 내보내기, 표시 화면에 남기지 않습니다. 호스트 화면에만 보여 줍니다 |
| 저장 파일에 코드가 섞여 나감 | 접속 코드는 Event에 저장되지만 **JSON 내보내기에서 기본으로 뺍니다.** 코드까지 내보내려면 따로 선택해야 하고, 그때 경고를 보여 줍니다 |
| 파일 불러오기로 깨뜨리기 | 불러온 JSON을 스키마로 검증하고 개수·길이·좌표 범위 상한을 둡니다. 원호는 꼭짓점 번호가 실제로 가리킬 수 있는 것만, 구역은 종류 화이트리스트에 든 것만 남깁니다 |

## 11. 한계와 제약 (문서와 화면에 명시)

- **일반 http 주소에서는 클라이언트 기기에 서비스 워커가 동작하지 않습니다.**
  접속한 기기는 오프라인 설치가 되지 않고, 호스트가 켜져 있어야 씁니다.
  호스트 기기에서 혼자 쓰는 모드는 영향받지 않습니다.
- 호스트를 끄면 접속 기기들의 실시간 기능이 멈춥니다. 표시 화면은 마지막 내용을
  유지한 채 "연결 끊김"을 띄웁니다.
- **공공 와이파이에서는 기기 간 통신이 막혀 있을 수 있습니다**(AP 격리).
  공연장 전용 공유기를 권장합니다.
- Wake Lock API를 지원하지 않는 브라우저에서는 화면이 꺼질 수 있습니다.
  기기 설정에서 화면 꺼짐을 꺼 두도록 안내합니다.
- 호스트 없이 혼자 쓰는 모드(무대 설계, PA 조언)는 서버 없이 동작해야 합니다.
- **무대 경계 제한은 장비 중심 기준입니다.** 장비의 중심이 무대 다각형 안에
  있으면 통과시키므로, 오목한 변이나 호 근처에서는 모서리가 조금 걸칠 수
  있습니다. 회전 사각형을 임의의 다각형 안에 완전히 가두는 계산은 비용이 크고,
  곡선 가장자리에서 끌기가 걸리는 느낌을 줍니다. 무대보다 큰 장비는 중심이
  들어올 수 없으므로 왼쪽 위에 맞춥니다.
- **원형 템플릿은 가로 ≠ 세로일 때 타원의 근사입니다**(원호 넷). 정확한 타원이
  필요하면 꼭짓점을 더해 직접 다듬어야 합니다.
- 원호는 변마다 하나이며 반원보다 큰 호는 두지 않습니다. 더 깊은 곡선은 꼭짓점을
  더해 여러 호로 나눠 만듭니다.

## 12. 비기능 요구

- **대상 기기**: iPad Safari, 안드로이드 Chrome, 윈도우 터치(Chrome/Edge).
  데스크톱 브라우저에서도 똑같이 동작합니다.
- **입력**: Pointer Events 하나로 마우스·터치·펜을 함께 처리합니다.
  터치 영역은 44px 이상입니다.
- **오프라인**: 인터넷 없이 동작합니다. 글꼴과 모든 자산을 앱에 포함합니다.
- **실행**: 윈도우와 맥에서 모두 돌아갑니다. 실행 파일 패키징은 나중 단계입니다.
- **성능 목표**: 장비 200개까지 캔버스가 부드럽게 움직입니다.
  접속 기기 20대까지 공지 전파가 1초 안에 끝납니다.
- **저장**: 자동 저장(IndexedDB) + 파일 내보내기. 저장 실패는 화면에 알립니다.
- **글꼴**: Pretendard **서브셋**(한글 완성형 + 영문·숫자)을 앱에 포함합니다.
  표시 화면을 태블릿에서 빨리 띄우는 것이 중요하므로 가변 폰트 전체는 쓰지 않습니다.
- **PDF**: 별도 라이브러리 없이 **브라우저 인쇄(print CSS)**로 만듭니다.
