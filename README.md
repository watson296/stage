# Stage Planner

밴드·공연 무대를 위에서 본 평면도로 구상하는 도구입니다. 장비를 끌어다
놓고, 스태프 포스트잇을 붙이고, 배치를 JSON이나 이미지로 내보냅니다.
태블릿과 터치 화면에서 쓰도록 만들고, 인터넷 없이도 동작합니다.

> Think Better Act Smarter

## 무엇을 하나요

- 무대 모양을 템플릿 7종에서 고르고, 꼭짓점을 끌어 고칩니다. 변 중점을 끌면
  곡선(원호)이 됩니다.
- 장비 15종(드럼킷, 앰프, 스피커, 믹서 등)과 직접 추가한 커스텀 장비를
  미터 격자에 맞춰 배치합니다. 크기와 회전은 손잡이나 숫자로 조절합니다.
- 구역을 그립니다. 라이저·단차는 높이를, 객석·FOH·출입구·대기실 동선은
  무대 밖 자리를 표시합니다.
- 스태프 메모를 붙이고 장비와 연결선으로 잇습니다.
- 공연장 정보와 편성을 넣으면 PA 기본 세팅을 조언합니다. 메인·서브·모니터 수,
  딜레이 스피커 지연, 예상 음압, 입력 채널 리스트 초안, 전원 점검을 근거 공식과
  함께 보여 주고, 결과를 도면에 배치 초안으로 넣습니다.
- 하루 순서(타임테이블)를 만들고 공연 중에 시작·종료를 기록합니다. 한 순서가
  밀리면 뒤 순서의 예상 시각을 다시 계산하고, 목록과 가로 타임라인으로 봅니다.
- 같은 와이파이의 기기들이 호스트에 붙어 같은 내용을 봅니다. 인터넷은 필요
  없습니다. 역할별 접속 코드로 들어가고, 권한은 호스트가 확인합니다.
- 공연 중에는 운영 대시보드로 순서를 시작·종료하고 공지를 보냅니다. 대기실
  TV와 스태프 태블릿, 무대 뒤 큐 화면은 읽기 전용 큰 글씨로 같은 내용을
  보여 주고, 긴급 공지는 화면을 덮습니다.
- 배치를 JSON으로 저장하고 다시 불러옵니다. PNG와 PDF로 내보냅니다.

## 쓰는 방법 세 가지

| 방법 | 필요한 것 | 할 수 있는 일 |
|---|---|---|
| 노트북에서 혼자 쓰기 | 노트북 한 대 | 무대 설계, PA 조언, 타임테이블 편집과 진행 기록, 저장·내보내기 |
| iPad·태블릿에서 쓰기 | 노트북 한 대(앱을 띄워 주는 역할) + 같은 와이파이 | 위와 같은 기능을 태블릿 화면과 터치로 씁니다 |
| 호스트를 열어 함께 쓰기 | 노트북 한 대(호스트) + 같은 와이파이의 기기들 | 위 기능 + 여러 기기가 같은 내용을 실시간으로 봅니다. 대시보드, 공지, 대기실·스태프·큐 화면 |

**iPad나 휴대폰만으로는 앱을 띄울 수 없습니다.** 이 앱은 노트북(Windows 또는
macOS)에서 Node.js로 띄우고, 태블릿과 휴대폰은 그 노트북의 주소를 브라우저로
열어 씁니다. 앱스토어 앱이나 설치 파일은 아직 없습니다.

인터넷은 필요 없습니다. 같은 와이파이(공유기)만 있으면 됩니다. 처음 설치할
때만 인터넷이 필요합니다.

## 준비: 노트북에 설치하기

처음 한 번만 하면 됩니다. 인터넷이 되는 곳에서 미리 해 둡니다.

### 1. Node.js 설치

- [nodejs.org](https://nodejs.org/)에서 **LTS 버전(22 이상)** 을 받아 설치합니다.
- 호스트 서버는 TypeScript 파일을 Node.js로 바로 실행합니다. 이 기능은 오래된
  Node.js에는 없으므로 **22 LTS의 최신 판**을 씁니다. (Node.js v22.23.5에서
  동작을 확인했습니다.)
- 설치가 됐는지 터미널(Windows는 "명령 프롬프트" 또는 "PowerShell", macOS는
  "터미널")에서 확인합니다.

```bash
node -v    # v22.x.x 처럼 나오면 됩니다
```

### 2. 소스 받기

Git을 쓴다면:

```bash
git clone https://github.com/watson296/stage.git
cd stage
```

Git이 없다면 GitHub 페이지의 **Code → Download ZIP**으로 받아 압축을 풀고,
터미널에서 그 폴더로 들어갑니다(`cd 폴더경로`).

### 3. 의존성 설치와 빌드

```bash
npm install
npm run build
```

`npm run build`가 끝나면 `packages/app/dist/` 폴더에 앱이 만들어집니다.
호스트 서버는 이 폴더를 다른 기기에 보내 줍니다. **소스를 새로 받거나 고친
뒤에는 `npm run build`를 다시 실행합니다.**

## 노트북에서 혼자 쓰기

가장 간단한 방법은 호스트 서버를 띄우고 노트북 브라우저로 여는 것입니다.

```bash
npm run host
```

브라우저(Chrome, Edge, Safari)에서 `http://localhost:7321` 을 엽니다. 접속
코드를 넣지 않아도 무대 설계, PA 조언, 타임테이블은 모두 씁니다. 작업은
그 브라우저에 자동 저장(IndexedDB)됩니다.

> **자동 저장은 "주소별"입니다.** `http://localhost:7321` 에서 만든 작업은
> `http://192.168.0.5:7321` 이나 `http://localhost:5173`(개발 서버)에서
> 열면 보이지 않습니다. 브라우저가 주소마다 저장소를 따로 두기 때문입니다.
> 다른 주소나 다른 기기로 옮길 때는 **저장(JSON) → 불러오기**를 씁니다.

### 저장과 내보내기

| 단추 | 하는 일 |
|---|---|
| 저장 | 공연 전체를 JSON 파일로 내려받습니다. 접속 코드는 들어가지 않습니다 |
| 불러오기 | JSON 파일을 열어 지금 내용을 바꿉니다 |
| PNG 내보내기 | 무대 도면을 그림 파일로 받습니다(무대 설계 화면) |
| PDF 내보내기 | 브라우저 인쇄 창을 엽니다. "PDF로 저장"을 고릅니다(무대 설계 화면) |

중요한 작업은 **저장(JSON)으로 파일을 꼭 남겨 둡니다.** 브라우저 저장소는
기록 지우기나 사생활 보호 모드에서 사라질 수 있습니다.

## iPad·태블릿·휴대폰에서 쓰기

### 원리

노트북이 앱을 띄우고(호스트 서버), 태블릿은 같은 와이파이로 그 노트북의 주소를
엽니다. 태블릿에서 접속 코드를 넣지 않으면 **태블릿 혼자 쓰는 모드**이고,
작업은 태블릿 브라우저에 저장됩니다. 팀원과 같은 내용을 함께 보려면
[호스트를 열어 팀원과 함께 쓰기](#호스트를-열어-팀원과-함께-쓰기)를 따릅니다.

### 순서

1. 노트북과 태블릿을 **같은 와이파이**에 연결합니다.
2. 노트북에서 호스트를 띄웁니다.

   ```bash
   npm run host
   ```

3. 터미널에 나온 **접속 주소**를 확인합니다.

   ```
     호스트를 시작했습니다.
     접속 주소: http://192.168.0.5:7321/
   ```

4. 태블릿의 Safari(iPad) 또는 Chrome(안드로이드)에서 그 주소를 그대로 입력합니다.
   `http://` 와 `:7321` 까지 모두 넣습니다.
5. 처음 열 때 노트북에 **방화벽 허용 창**이 뜨면 허용합니다.
   ([문제 해결](#문제-해결)의 방화벽 항목 참고)

주소를 손으로 치기 번거로우면 노트북 브라우저에서
`http://localhost:7321/qr.svg` 를 열어 QR 코드를 띄우고, 태블릿 카메라로
찍습니다. QR에는 3번의 접속 주소가 들어 있습니다.

### 홈 화면에 추가 (선택)

iPad Safari의 공유 단추 → **홈 화면에 추가**로 아이콘을 만들 수 있습니다.
다만 아이콘으로 열어도 **노트북의 호스트가 켜져 있어야** 열립니다. 일반
`http://` 주소에서는 오프라인 설치(서비스 워커)가 되지 않기 때문입니다
(SPEC 11장).

### 터치 조작

| 하고 싶은 일 | 방법 |
|---|---|
| 장비 놓기 | 왼쪽 목록에서 장비를 탭하거나 끌어 놓습니다 |
| 고르기·옮기기 | 장비를 탭해 고르고 끌어 옮깁니다 |
| 화면 이동·확대 | 두 손가락으로 끌기, 두 손가락 벌리기·오므리기 |
| 크기·회전 | 고른 장비의 손잡이를 끌거나, 아래 속성 바에 숫자를 넣습니다 |
| 무대 모양 고치기 | 위 도구 줄의 "무대 모양"에서 꼭짓점을 끕니다. 변 가운데 손잡이를 끌면 곡선이 됩니다 |
| 화면에 맞추기 | 도구 줄의 "맞춤" |

키보드를 붙인 iPad에서는 `Ctrl`/`⌘`+`Z`(되돌리기), `Ctrl`/`⌘`+`Shift`+`Z`
또는 `Ctrl`/`⌘`+`Y`(다시 실행), `R`(회전), `Delete`·`Backspace`(지우기)도
됩니다.

### 태블릿에서 주의할 점

- **화면 자동 꺼짐을 꺼 둡니다.** 표시 화면은 화면 꺼짐 방지(Wake Lock)를
  쓰지만, 이 기능은 브라우저가 `https://` 나 `localhost` 주소에서만 허락합니다.
  `http://192.168.x.x` 로 연 태블릿에서는 동작하지 않습니다(Chromium에서
  확인). 대기실 TV나 큐 화면으로 쓸 태블릿은 기기 설정에서 직접 꺼 둡니다.
  - iPad: 설정 → 디스플레이 및 밝기 → 자동 잠금 → 안 함
  - 안드로이드: 설정 → 디스플레이 → 화면 자동 꺼짐(기기마다 이름이 다릅니다)
- **iPad Safari는 오래 쓰지 않은 사이트의 저장소를 비울 수 있습니다.** 태블릿
  혼자 쓰는 모드로 작업했다면 "저장"으로 JSON 파일을 남겨 둡니다. Safari에서
  내려받은 파일은 보통 파일 앱의 "다운로드"에 들어갑니다.
- 태블릿 화면 크기(iPad 가로)에서 무대 설계 화면이 깨지지 않는 것은 확인했지만,
  **실제 iPad·안드로이드 기기에서의 점검은 아직 하지 않았습니다**(ROADMAP 7단계).
  문제가 보이면 이슈로 알려 주세요.

## 호스트를 열어 팀원과 함께 쓰기

노트북 한 대를 **호스트**로 띄우면 같은 와이파이의 기기들이 접속해 같은 내용을
봅니다. 호스트가 데이터의 원본입니다. 운영자가 고친 내용은 0.4초 안에 모든
기기에 퍼집니다.

```
          [ 공유기 / 와이파이 ]
                  │
   ┌──────────────┼───────────────┬──────────────┐
 호스트 노트북   운영자 태블릿    스태프 휴대폰    대기실 TV
 (npm run host)  (운영자 코드)    (스태프 코드)    (표시 화면 코드)
```

### 역할

접속할 때 넣는 **6자리 코드가 역할을 정합니다.** 코드는 역할마다 다릅니다.

| 역할 | 할 수 있는 일 | 주로 쓰는 기기 |
|---|---|---|
| 운영자 | 모든 편집, 공지 보내기, 순서 시작·종료, 기기 끊기 | 운영 노트북, 무대감독 태블릿 |
| 스태프 | 공지 확인, **자기가 담당인 순서**만 시작·종료. 나머지는 읽기만 | 스태프 휴대폰 |
| 표시 화면 | 읽기만. 긴급 공지 확인(닫기)만 됩니다 | 대기실 TV, 무대 뒤 큐 태블릿 |

권한은 호스트가 검사합니다. 읽기 전용 기기에는 "읽기 전용입니다"가 보이고
편집 단추가 숨겨집니다.

### 0단계: 공연장 네트워크 준비

- **공연장 전용 공유기를 권장합니다.** 카페·학교·공공 와이파이는 기기끼리
  통신을 막아 둔 경우가 많습니다(AP 격리). 이때는 주소를 넣어도 접속이 안 됩니다.
- 공유기는 인터넷에 연결되어 있지 않아도 됩니다.
- 휴대폰 핫스팟도 쓸 수 있습니다. 노트북과 다른 기기를 모두 그 핫스팟에
  붙입니다. (기종에 따라 핫스팟 기기끼리 통신을 막는 경우가 있어, 공연 전에
  꼭 시험해 봅니다.)
- 호스트는 **사설 IP 주소**(10.x.x.x, 172.16~31.x.x, 192.168.x.x 등)에서 오는
  연결만 받습니다. 인터넷에서 들어오는 연결은 거부합니다.

### 1단계: 공연 파일을 준비합니다 (중요)

> **주의 — 지금 버전에서는 운영자가 호스트에 접속하는 순간, 그 기기의 작업이
> 호스트의 내용으로 바뀝니다.** 호스트를 빈 공연으로 띄우고 운영자가 접속하면,
> 운영자 기기에서 만들어 둔 도면과 타임테이블이 빈 공연으로 덮이고 자동
> 저장까지 덮입니다. (직접 재현해 확인한 동작입니다. 아래
> [알려진 문제](#알려진-문제-고치기-전까지-주의할-점) 참고)

그래서 **접속하기 전에 먼저 작업을 JSON 파일로 저장해 둡니다.**

1. 작업한 기기에서 **저장** 단추를 눌러 JSON 파일을 받습니다
   (예: `공연.json`).
2. 그 파일을 호스트 노트북으로 옮깁니다. 아래 2단계에서 호스트를 띄울 때
   이 파일을 넘기면 됩니다.

### 2단계: 호스트를 띄웁니다

호스트 노트북의 터미널에서 저장소 폴더로 들어가 실행합니다.

```bash
npm run build    # 처음이거나 소스를 고쳤을 때만
npm run host -- -- --file "C:/Users/나/Desktop/공연.json"
```

- **`--` 를 두 번 씁니다.** 지금 스크립트 구조에서는 `--` 를 한 번만 쓰면
  `--file`, `--port` 같은 옵션이 서버에 전달되지 않고 무시됩니다(알려진 문제).
- **파일 경로는 절대 경로로 씁니다.** 상대 경로(`--file 공연.json`)를 쓰면
  저장소 루트가 아니라 `packages/server/` 폴더를 기준으로 찾고 저장합니다.
  macOS 예: `--file "/Users/나/Desktop/공연.json"`
- 파일이 아직 없으면 빈 공연으로 시작하고, 끝낼 때 그 경로에 새로 저장합니다.

쓸 수 있는 옵션은 다음과 같습니다.

| 옵션 | 뜻 | 기본값 |
|---|---|---|
| `--file <경로>` | 시작할 때 읽고, 끝낼 때(Ctrl+C) 저장할 공연 파일 | 없음(저장 안 함) |
| `--port <번호>` | 접속 포트 | `7321` |
| `--address <IP>` | 접속 주소와 QR에 쓸 IP. 네트워크가 여럿일 때 고릅니다 | 자동 |
| `--allow-public` | 사설 IP 제한을 풉니다. **인터넷에 노출될 수 있어 권하지 않습니다** | 꺼짐 |

예: `npm run host -- -- --port 8080 --file "/Users/나/공연.json" --address 192.168.0.5`

실행하면 터미널에 이렇게 나옵니다(코드는 실행할 때마다 다르게 보입니다).

```
  호스트를 시작했습니다.
  접속 주소: http://192.168.0.5:7321/

  접속 코드 (이 화면에만 보여 줍니다)
    운영자    ●●●●●●
    스태프    ●●●●●●
    표시 화면 ●●●●●●

  끝내려면 Ctrl+C 를 누릅니다.
```

- **이 터미널 창은 공연이 끝날 때까지 닫지 않습니다.** 닫으면 모든 기기의
  실시간 연결이 끊깁니다.
- **접속 코드는 이 화면에만 나옵니다.** 사진을 찍어 단체방에 올리지 말고,
  역할에 맞는 사람에게만 따로 알려 줍니다. 특히 운영자 코드는 모든 것을
  고칠 수 있습니다.
- 네트워크가 여럿이면(유선 + 와이파이 등) "이 기기의 다른 주소" 목록이
  나옵니다. 다른 기기에서 접속이 안 되면 와이파이 쪽 주소를 `--address` 로
  골라 다시 띄웁니다.
- `--file` 로 띄우면 껐다 켜도 **같은 접속 코드**를 씁니다. 코드는 그 파일에
  함께 저장되기 때문입니다.

### 3단계: 운영자가 접속합니다

1. 운영자 기기의 브라우저에서 접속 주소를 엽니다. 호스트 노트북 자신이라면
   `http://localhost:7321` 을 열어도 됩니다.
2. 위쪽 탭에서 **호스트**를 누릅니다.
3. **호스트에 접속** 칸을 채웁니다.
   - 호스트 주소: 이미 채워져 있습니다(지금 연 주소). 그대로 둡니다.
   - 접속 코드: 운영자 코드 6자리
   - 역할: **운영자**
   - 이 기기 이름: 예) `운영 노트북`
4. **접속**을 누릅니다. 상태가 "접속됨"으로 바뀌고 탭에 "호스트 (접속됨)"이
   보입니다.
5. 호스트를 `--file` 없이 띄웠다면, 접속한 **뒤에** 위쪽의 **불러오기**로
   1단계에서 저장한 JSON을 엽니다. 불러온 내용이 곧바로 호스트에 올라가
   모든 기기에 퍼집니다(직접 확인한 동작입니다).

> 접속 후 화면에 보이는 "지금 작업을 호스트에 올리기" 단추는 **접속한 뒤에
> 고친 내용**을 올립니다. 접속 전에 만든 작업은 이미 덮인 뒤라 이 단추로
> 되살릴 수 없습니다. 꼭 위의 불러오기 방법을 씁니다.

접속에 성공하면 호스트 화면에 **접속 QR 코드**와 **접속 기기 목록**이 보입니다.
팀원에게 QR을 보여 주면 됩니다. 모르는 기기가 보이면 **끊기**로 내보냅니다.

### 4단계: 팀원이 접속합니다

각 기기에서:

1. 같은 와이파이에 연결합니다.
2. 브라우저로 접속 주소를 열거나 QR을 찍습니다.
3. **호스트** 탭 → 접속 코드, 역할, 기기 이름을 넣고 **접속**을 누릅니다.
   - 코드와 역할이 맞아야 합니다. 스태프 코드로 역할을 "운영자"로 고르면
     거부됩니다.

**스태프는 기기 이름을 타임테이블의 "담당" 칸과 똑같이 씁니다.** 스태프가
순서를 시작·종료할 수 있는지는 "담당 이름 = 기기 이름"으로 판단합니다.
앞뒤 공백은 무시하지만, 띄어쓰기나 글자가 하나라도 다르면 거부됩니다.
(예: 담당이 `김무대` 라면 기기 이름도 `김무대`)

### 5단계: 공연 중에 쓰는 화면

| 탭 | 누가 | 하는 일 |
|---|---|---|
| 대시보드 | 운영자 | 지금·다음 순서, 남은 시간, 누적 지연. 순서 시작·종료. 공지 보내기(일반·긴급)와 확인한 기기 수 |
| 타임테이블 | 운영자, 스태프 | 순서 목록과 진행 기록. 스태프는 자기 담당 순서의 "시작"·"종료"만 됩니다 |
| 표시 화면 | 표시 화면 역할 | 오른쪽 위에서 화면 종류를 고릅니다. **대기실**(지금·남은 시간·다음·콜 타임), **스태프**(전환 지시와 담당), **무대 뒤 큐**(순서 이름과 남은 시간만 아주 크게) |

- 남은 시간은 **호스트의 시계**를 기준으로 계산하므로 모든 기기가 같은
  숫자를 봅니다. 기기 시계가 조금 틀려도 괜찮습니다.
- **긴급 공지**는 화면 전체를 덮습니다. 그 기기에서 "확인"을 눌러야
  사라지고, 운영자 대시보드에 확인한 기기 수가 올라갑니다.
- 와이파이가 잠깐 끊기면 화면은 마지막 내용을 그대로 두고 "연결 끊김"을
  띄운 뒤 **자동으로 다시 접속**합니다.
- 대기실 TV로 쓸 때는 브라우저의 전체 화면(Windows Chrome/Edge는 `F11`)을
  쓰면 주소창이 사라집니다.

### 6단계: 끝내기

1. 운영자 기기에서 **저장**으로 최종 JSON을 받아 둡니다(백업).
2. 호스트 터미널에서 `Ctrl+C` 를 누릅니다. `--file` 로 띄웠다면
   `... 에 저장했습니다.` 가 나오고 그 파일에 저장됩니다.

> `--file` 로 저장한 파일에는 **접속 코드가 들어 있습니다.** 다른 사람에게
> 공연 파일을 줄 때는 이 파일이 아니라 앱의 **저장** 단추로 받은 JSON을
> 줍니다. 그쪽에는 코드가 빠져 있습니다.

### 공연 전 점검표

- [ ] 호스트 노트북 충전기 연결, 절전·화면 꺼짐 끄기

- [ ] 공연장 공유기에 노트북과 모든 기기를 붙여 실제로 접속해 봄

- [ ] 긴급 공지를 한 번 보내 모든 화면에 뜨고 닫히는지 확인

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 태블릿에서 주소를 열면 계속 로딩되다 실패함 | ① 같은 와이파이인지 ② 주소에 `http://` 와 `:7321` 이 있는지 ③ 방화벽(아래) ④ 공공 와이파이의 AP 격리 ⑤ 네트워크가 여럿이면 `--address` 로 와이파이 쪽 주소를 고름 |
| Windows에서 다른 기기가 접속 못 함 | 처음 실행할 때 뜨는 "Windows 보안 경고"에서 Node.js를 **개인 네트워크**에 허용합니다. 이미 거부했다면 제어판 → Windows Defender 방화벽 → "앱 허용"에서 Node.js를 켭니다. 와이파이가 "공용 네트워크"로 잡혀 있으면 "개인 네트워크"로 바꿉니다 |
| macOS에서 다른 기기가 접속 못 함 | "들어오는 네트워크 연결을 허용하겠습니까?" 창에서 **허용**. 시스템 설정 → 네트워크 → 방화벽에서 node가 차단되어 있지 않은지 봅니다 |
| "같은 네트워크 안에서만 접속할 수 있습니다." | 접속한 기기의 IP가 사설 대역이 아닙니다(VPN, 일부 통신사·핫스팟 대역 등). VPN을 끄고 같은 공유기에 붙입니다. `--allow-public` 은 정말 필요할 때만 씁니다 |
| "접속 코드가 맞지 않습니다." | 호스트 터미널의 코드를 다시 봅니다. 코드와 **역할 선택이 짝이 맞아야** 합니다 |
| "접속 시도가 많아 N초 뒤에 다시 됩니다." | 같은 IP에서 10분 안에 5번 틀리면 60초 동안 막힙니다. 잠시 기다립니다 |
| 스태프가 "시작"을 누르면 "이 역할로는 할 수 없는 동작입니다." | 기기 이름과 그 순서의 담당 이름이 다릅니다. 접속 끊기 → 이름을 맞춰 다시 접속 |
| 표시 화면 태블릿이 꺼짐 | 기기 설정에서 자동 잠금을 끕니다([태블릿에서 주의할 점](#태블릿에서-주의할-점)) |
| `npm run host` 에 준 `--port`, `--file` 이 무시됨 | `--` 를 두 번 씁니다: `npm run host -- -- --port 8080` |
| "배포 빌드가 없습니다." | `npm run build` 를 먼저 실행합니다 |
| 호스트 터미널이 오류를 내고 꺼짐 | 아래 알려진 문제 ①을 따릅니다 |

## 알려진 문제 (고치기 전까지 주의할 점)

아래는 지금 코드에서 직접 재현한 문제입니다. 고치기 전까지는 안내한 방법으로
피해 갑니다.

1. **호스트가 특정 요청에 꺼질 수 있습니다.** 잘못된 주소(예: 깨진 `%` 문자가
   든 URL)나 64KB가 넘는 메시지 하나로 호스트 프로세스가 종료됩니다. 장비를
   약 400개 넘게 놓은 큰 도면은 운영자의 정상적인 편집만으로도 64KB를 넘을 수
   있습니다.
   - 호스트가 꺼지면 **호스트를 다시 띄우기 전에** 운영자 기기에서 먼저
     **저장(JSON)** 을 누릅니다. 호스트가 다시 뜨면 운영자 기기가 자동으로
     다시 접속하면서 내용이 호스트의 것(빈 공연 또는 마지막으로 저장된 파일)으로
     바뀌기 때문입니다.
   - 그다음 호스트를 다시 띄우고, 운영자가 **불러오기**로 그 JSON을 엽니다.
   - `--file` 저장은 `Ctrl+C` 로 정상 종료할 때만 일어납니다. 갑자기 꺼지면
     파일은 마지막으로 정상 종료한 때의 내용 그대로입니다.
2. **운영자가 접속하면 그 기기의 작업이 호스트 내용으로 덮입니다.**
   [1단계](#1단계-공연-파일을-준비합니다-중요)대로 미리 저장하고 `--file`
   이나 불러오기로 올립니다.
3. **`npm run host -- --옵션` 이 옵션을 전달하지 못합니다.** `--` 를 두 번 씁니다.
4. **`--file` 상대 경로는 `packages/server/` 기준입니다.** 절대 경로를 씁니다.
5. **같은 연결에서 접속을 두 번 하면 접속 기기 목록에 유령 기기가 남을 수
   있습니다.** 목록에 같은 이름이 둘 보이면 무시해도 됩니다.
6. **스태프 권한은 기기 이름으로만 확인합니다.** 스태프 코드를 아는 사람은
   다른 담당자 이름으로 접속해 그 순서를 시작·종료할 수 있습니다. 스태프
   코드는 믿을 수 있는 사람에게만 줍니다.

## 개발자용

```bash
npm install          # 의존성 설치
npm run dev          # 개발 서버 (http://localhost:5173)
npm run build        # 타입 검사 + 배포용 빌드 (packages/app/dist)
npm run build:single # 단일 HTML 파일로 빌드
npm test             # 테스트 실행 (vitest)
npm run typecheck    # 타입 검사
npm run host         # 호스트 서버 (빌드 뒤에 실행합니다)
```

개발 중에 태블릿에서 바로 보고 싶다면 개발 서버를 네트워크에 엽니다.
여기서도 `--` 를 두 번 씁니다.

```bash
npm run dev -- -- --host
#   ➜  Network: http://192.168.0.5:5173/   ← 태블릿에서 이 주소를 엽니다
```

개발 서버로 연 앱은 호스트 서버(7321)와 주소가 달라 자동 저장도 따로입니다.
실시간 기능을 시험할 때는 `npm run build` 후 `npm run host` 로 띄운 주소에서
시험합니다.

`npm run build:single` 로 만든 HTML 파일 하나를 태블릿에서 직접 여는 방법은
아직 실제 기기에서 확인하지 않았습니다.

### 저장소 구조

```
packages/
├── app/      브라우저 앱 (Vite + Preact)
├── server/   호스트 서버 (Node.js, ws)
└── shared/   데이터 스키마, 계산 함수, 메시지 타입
```

스택은 Vite + TypeScript + Preact이고 테스트는 vitest입니다. 좌표는 모두
미터 단위의 월드 좌표이며, 입력은 Pointer Events로 마우스·터치·펜을 함께
처리합니다.

자세한 명세는 [docs/SPEC.md](docs/SPEC.md), 앞으로의 계획은
[docs/ROADMAP.md](docs/ROADMAP.md)를 보세요.
